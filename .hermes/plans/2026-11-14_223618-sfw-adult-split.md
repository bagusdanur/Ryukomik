# Pisahkan Mode 18+ — SFW Total Sekarang, Situs Dewasa Terpisah Nanti

**Goal:** `ryukomik.com` jadi situs **SFW murni tanpa sakelar 18+ sama sekali**, dan semua mesin konten dewasa dipindah ke situs kedua (deployment terpisah) yang bisa dinyalakan belakangan dari codebase yang sama.

**Architecture:** Satu codebase, dua deployment. Perilaku ditentukan satu variabel `NEXT_PUBLIC_SITE_MODE` (`sfw` | `adult`). Di mode `sfw`, konten dewasa **disembunyikan di server** (bukan lewat cookie preferensi pengguna), dan seluruh UI sakelar/blur/consent dihapus dari tampilan. Di mode `adult`, semuanya hidup lagi dengan gerbang usia wajib. Data di database **tidak dihapus** — hanya tidak pernah dikirim ke klien SFW.

**Tech Stack:** Next.js App Router, PostgreSQL (project + social DB), PM2, nginx, Cloudflare.

Permintaan "hapus total" gampang dipenuhi dengan menghapus 61 file — tapi situs kedua nanti harus dibangun ulang dari nol, dan itu kerja dobel. **Files:** Create `src/config/siteMode.ts`

/** Semua jalur konten dewasa (sumber, project is_adult, post sensitif) hidup hanya di sini. */

### Task 3: Server hard-hide (bukan cookie)

**Files:** Modify `src/lib/adultPrefServer.ts`

```ts
import { ADULT_ENABLED } from "@/config/siteMode";

export async function adultContentHidden(): Promise<boolean> {
  if (!ADULT_ENABLED) return true;   // SFW: selalu sembunyi, abaikan cookie
  return (await cookies()).get(ADULT_PREF_COOKIE)?.value === "1";
}
```

Ini yang membalik default: SFW tidak lagi bergantung pada pilihan pengunjung.

**Verifikasi:** buka `/` di mode SFW → tidak ada kartu dewasa meski cookie kosong.

## FASE 2 — Situs dewasa (nanti, setelah Fase 1 stabil)

Ringkas saja, detailnya dibuat saat mau dieksekusi.

1. **Domain terpisah, bukan subdomain.** Cookie sesi hari ini di-set `domain=.ryukomik.com`. Kalau situs dewasa ditaruh di `18.ryukomik.com`, cookie login ikut terbawa — satu kebocoran preferensi/usia dan satu laporan saja bisa menjatuhkan domain utama. Pakai domain sendiri.
2. **Instance kedua:** `pm2 start` dengan `NEXT_PUBLIC_SITE_MODE=adult`, port baru (mis. 3009), build terpisah di folder lain.
3. **vhost nginx** sendiri + Cloudflare zone sendiri.
4. **Database sama, baca-tulis.** Tidak perlu duplikasi; `is_adult` / `is_sensitive` sudah jadi penanda.
5. **Gerbang usia wajib** di situs dewasa: interstitial sekali per sesi, tidak bisa di-skip tanpa konfirmasi 18+.
6. **Iklan & pembayaran dipisah.** Monetag/ads SFW jangan dipasang di situs dewasa, dan sebaliknya — pencampuran ini yang biasanya memicu penolakan akun.
7. **Tanpa saling-link.** Situs SFW tidak menautkan situs dewasa; situs dewasa tidak menautkan balik ke SFW di area publik.

## Risks

- **Traffic 18+ hilang dari domain utama.** Itu memang tujuannya, tapi kalau situs kedua belum siap, pengunjung itu tidak punya tempat tujuan. Mitigasi: luncurkan situs kedua **sebelum** atau bersamaan, bukan berbulan-bulan sesudah.
- **410 di `/hentai` menurunkan angka indeks Google** dalam 1-4 minggu. Normal dan diinginkan.
- **Sakelar yang terlanjur dimatikan pengguna.** Setelah toggle dihapus, cookie `rk_hide_adult` jadi tak terpakai — bersihkan di Task 3 (abaikan nilainya).
- **Dua deployment = dua build.** Setiap rilis harus di-deploy dua kali kalau situs kedua sudah hidup. Catat di runbook.
